# App 模板化流程（GitHub Actions 标准路线）

> **主人钦定（2026-09-11）** — 新建任何 Android App 一律走本流程，不另起炉灶。
> **2026-09-23 补丁**：有界面的 App，最前面先交前端，并用手机浏览器打开给主人看；确认后才做后面的事。手机预览命令见 §0.1，不许只给文件路径。
> 状态：生效中

---

## 0. 先拆解用户要求，再分步实现

拿到需求后，先把用户的原话拆成清单，不立刻把所有功能一次写完。

每一项只标三种状态：

- 已实现：真实流程已经可用。
- 半实现：只有界面、入口或演示数据。
- 未实现：还没有真实能力。

拆解后按依赖顺序一次做一项。每一项完成并验证后，再做下一项。不能把演示数据、搜索链接或模拟结果说成真实功能。

### 0.1 报错助手

拆解完成后，第一步先加报错助手。之后每一项功能都接入它。

- 页面上显示完整错误，不只写控制台。
- 覆盖按钮异常、接口失败、异步错误和输入错误。
- 错误可见、可关闭，不能被普通提示盖住。
- 没有报错助手，不开始下一项功能。

## 0.1 最前面：先写前端，本地打开浏览器看

有界面才走本节。纯后台、无界面的任务跳过，从 §1 开始。

顺序固定，不许调换：

1. **只写前端**（HTML/CSS/JS）。无 Android 桥时注入浏览器模拟桥（`window.AndroidRelay` 不存在才注入），交互在浏览器里可点。
2. **交一个本地可打开的文件**（例如 `prototype/index.html`）。不要只给文件路径。
3. **立刻在手机浏览器打开给主人看**。按下面的固定命令做，不要改：
   ```sh
   cd <前端目录>
   python3 -m http.server 8765 --bind 0.0.0.0
   ```
   查手机能访问的地址：`ip -4 addr show wlan0`，取 `192.168.*` 那一个。
   回复里必须给出完整地址，例如 `http://192.168.1.5:8765/index.html`。
   用这个地址自己请求一次，确认返回 200，再把地址交给主人。
4. 验收只看三件事：手机浏览器打得开、关键路径点得通、控制台没有未处理错误。
5. **主人确认这个前端之后**，才做 §3 的仓库、治理、构建、调用蓝图、原生层和 APK。

低级模型禁止：

- 禁止只回文件路径，假装主人能打开。
- 禁止绑 `127.0.0.1`。那个地址手机打不开。
- 禁止把 `172.*`、`tun0` 的地址当成手机地址。只用 `wlan0` 的 `192.168.*`。
- 禁止让主人去装服务器、开 GitHub Pages，或和电脑连同一个 Wi-Fi 以外的额外步骤。

硬约束：

- 这一步不建仓库、不配签名、不写 Java/Kotlin、不触发 Actions。
- 主人确认过的这份前端，就是之后 WebView 的唯一视觉基准；禁止用原生控件再仿一套 UI。
- 演示数据只留在这份原型里。正式 APK 默认真实空状态。

## 0.2 安卓 APP 界面格式（2026-09-30 主人钦定）

**这是唯一允许的界面格式。以后所有安卓 App 前端都照这个做，不要再自己发明。**

### 一句话规矩

**底部 Tab 切换 + 每个 Tab 只装自己那几步 + 单列卡片纵向排。**
不做长网页，不做横向滚动的"网页风"。

### 硬性结构

```
<header>  顶栏：返回键 + 标题(ab-name) + 副标题(ab-sub) + 右侧操作
<main>
  <section class="screen" id="tab-*">   ← 一屏一个 Tab，切换靠 class="on"
    <div class="steps">                 ← 该 Tab 的步骤卡，纵向排
      <div class="step-card" id="sN">   ← 一步一张卡
    </div>
  </section>
<nav class="dock">                      ← 底部固定 5 个 Tab，不在内容流里
```

### 五 Tab 分工（通用模板）

| Tab | 装什么 | 定位 |
|---|---|---|
| 工作台 | 起步的第 1-N 步 | 任务推进器 |
| 第二 Tab | 中段步骤 | 该类数据专属 |
| 第三 Tab | 中段步骤 | 同上 |
| 第四 Tab | 后段步骤 + 指标 | 看板/阈值 |
| 档案 | 尾段步骤 + 长期资料 | 档案柜 |

**核心原则**：`工作台 = 任务进度推进器，其他 Tab = 各维度的专属数据档案柜`。
禁止把全部步骤堆进工作台，让其他 Tab 变成摆设。

### 洛工坊实例（可直接照抄的分法）

| Tab | 承载内容 | 分段名 |
|---|---|---|
| 工作台 | 0 企划 · 1 设计词 · 2 出图 | 前期策划 |
| 款式库 | 2.5 图透投票 · 3 拆件 · 4 查重原创 | 定稿与合规 |
| 预售 | 5 采购 · 6 组合 · 7 模特 | 实物打样 |
| 看板 | 8 工厂 · 9 成本 · 10 定样 | 生产与定价 |
| 档案 | 11 预售 · 12 成团 · 13 大货 · 14 售后 | 开团与收尾 |

### 必须遵守的视觉规格

- **纵向单列**，卡片之间有 `margin-bottom` 留白；**禁止横向长条、禁止网格平铺**。
- 每张卡：**步骤号圆标 + 衬线体大标题 + 灰色小字提示 + 内容区**。
- 主按钮宽度 100%，放在卡片内容底部。
- 底部 dock 固定悬浮，**5 个 Tab**，`data-tab` 与 section 的 `id="tab-<name>"` 一一对应。
- 顶栏副标题在非工作台 Tab 时，显示**当前步 + 第 N / M 步**。

### ⛔ 两条用血换来的教训（必须写进任何新 App）

**教训 1：禁止"靠 JS 控制元素可见性"作为唯一显示手段。**
踩过的坑：为了做"一屏一张卡"，把 CSS 写成 `.step-card{display:none}` + JS 加 `.now` 才显示。
结果 JS 一挂**整页白屏**，连顶栏都不剩。
**正确做法**：CSS 默认可见，JS 只做增强。任何"默认隐藏、JS 显示"的写法都是禁止的。

**教训 2：禁止裸引用全局对象，必须加 `window.` 前缀。**
踩过的坑：
```js
if(window.matchMedia && matchMedia('(hover:none)').matches)  // 后半截是裸引用
if(!skipPush && window.history && history.pushState)         // 同上
```
安卓 WebView / 老浏览器缺这些 API 时 → `ReferenceError` → **整个 IIFE 中断 → 所有按钮点不动**（页面能显示，但全屏是死的）。

**必须这样做**：开头统一兜底，任何裸全局都补空实现：
```js
var W = (typeof window !== 'undefined') ? window : {};
if(typeof W.matchMedia !== 'function'){ W.matchMedia = function(){ return { matches:false, addListener:function(){}, removeListener:function(){} }; }; }
if(!W.history){ W.history = { state:null, pushState:function(){}, replaceState:function(){}, back:function(){}, forward:function(){} }; }
```

### 交付前必须自测（缺一不可）

| 检查 | 方法 | 通过标准 |
|---|---|---|
| 五个 Tab 都能切 | 逐一点击 `dock button`，断言 `.screen.on` 唯一且为对应 tab | 5/5 |
| 按钮高亮跟着切 | 断言 `.dock button.on` 唯一 | 5/5 |
| 跨 Tab 跳转 | 点步骤条第 N 项，断言自动切到所属 Tab + 该步高亮 | 通过 |
| 无裸全局 | 正则扫描 `(?<![.\w])matchMedia\(` / `history\.` 等 | 0 命中 |
| 脚本无异常 | 真实 DOM 执行，捕获 error | 无 |

**判据**：`domtest.js` 这类逐按钮点击测试必须全绿，不能只做静态断言。

## 3.5 ⭐ 调用蓝图：设计期强制产物（2026-09-22 主人钦定）

> **触发事件**：futures-terminal 的模拟盘「策略」链路整条失效，被主人判定为 **App 重大失误**。
> 根因不是某一行写错，而是**设计期没有调用蓝图**——三条各自正常的约定凑一起才致命，
> 而任何「只画谁调用谁」的文档都抓不到。故立此规矩：**蓝图先于代码，不许后期返工补。**

### 三条硬规矩

1. **`docs/CALL-GRAPH.md` 是设计期产物**：在写第一行业务代码前提交初稿，之后每次改动同步。
2. **蓝图必须包含以下五张表**（缺一即不算蓝图）：
   - **模块分层表**：文件 → 所在层 → 职责 → **禁止事项**；依赖只能单向向下
   - **模块化阈值表**：单文件行数/字节、单函数行数、`document.` 次数、同一存储键的读写方数量（见 §3.6）
   - **存储键唯一事实源表**：每个键 → 唯一读写方 → 其他模块的合法入口（一个键两个读写方 = 缺陷）
   - **中央路由契约表**：页面 → 注册方 → 进入动作；事件名 → 触发点 → 处理；注册语义（组合还是覆盖）
   - **检查清单**：新增/修改视图时的必查项
3. **蓝图要有可执行部分**：配一个离线回归脚本（如 `scripts/ui-regression.js`），
   把蓝图里的关系逐条断言。**蓝图没被断言 = 蓝图会腐烂。**

### 必须写进蓝图的四条通用红线（本项目踩过）

| 红线 | 说明 |
|---|---|
| **注册语义必须显式声明** | 中央路由的 `registerPage`/`register` 是**组合**还是**覆盖**，必须在蓝图写明。覆盖语义 + 入口文件最后执行 = 静默吞掉所有视图钩子 |
| **视图导出对象不得带 `onEnter` 键** | 一旦入口用「反射叫 `View.onEnter`」，就把「页面钩子」和「任意方法」混为一谈，必然出现覆盖或漏调用。页面钩子只走中央路由 |
| **一个存储键只能有一个读写方** | 多处各自解析同一个 localStorage 键 = 改了 A 处 B 处不知道，现象就叫「数据未接通」。收敛到唯一事实源模块 + 变更广播 |
| **动态 HTML 禁止拼 `onclick="Fn('名字')"`** | 名字含引号会直接炸掉整个渲染。用 `data-*` 属性 + 容器事件委托（只绑一次） |

### 母版参考

- 实例：`futures-terminal/docs/CALL-GRAPH.md`
- 可执行回归：`futures-terminal/scripts/ui-regression.js`（29 项断言，退出码 0/1）
- 架构技能：`route-registry`（「禁止覆写，改为注册」）、`route-verifier`（改路由后强制验证）

## 3.6 ⭐ 模块化：硬阈值与反模式（2026-09-22 主人钦定）

> 光说「要模块化」没用——必须给**数字**，否则每个 AI 的理解都不一样，最后还是揉成一个大文件。

### 拆分阈值（超了就拆）

| 信号 | 阈值 | 处置 |
|---|---|---|
| 单文件行数 | **> 400 行** | 按「职责」拆，不按行数平均切 |
| 单文件字节 | **> 30 KB** | 同上 |
| 单函数行数 | **> 60 行** | 抽子函数或抽模块 |
| `document.` 出现次数 | 一个文件里 **> 15 处** | 控制器与渲染混住了，拆渲染层 |
| 同文件既有 DOM 操作又有存储读写 | **出现即违规** | 状态存取抽到数据层 |
| 同一存储键读写方 > 1 个 | **出现即缺陷** | 收敛到唯一事实源模块 |

### 五层分层（WebView 类 App 通用，依赖只能向下）

```
基建（路由 / 入口） → 数据（唯一事实源） → 引擎（纯计算） → 渲染（纯函数） → 控制器（状态+DOM+事件）
```

| 层 | 允许 | 禁止 |
|---|---|---|
| 基建 | 调度、注册、导航 | 夹带业务逻辑 |
| 数据 | 读写存储、广播变更 | 碰 DOM |
| 引擎 | 纯计算（下单/指标/汇总） | 碰 DOM、碰存储 |
| 渲染 | 数据 → HTML / 图表 option | **碰 DOM、改状态** |
| 控制器 | 状态、DOM、注册事件 | 直接读写业务存储键 |

> ⚠️ **注意**：以上是针对 **WebView 类 App（前端 JS）**的模块化规范。
> 如果是**原生 Android Java/Kotlin**，需另建调用蓝图（见附录 B），核心表包括：
> - SharedPreferences 键唯一事实源表
> - Broadcast 注册表
> - Service 绑定表
> - Activity/Fragment 生命周期表

### 反模式清单

| 反模式 | 后果 | 正确做法 |
|---|---|---|
| 一个大文件装全部功能 | 改 A 碰坏 B，无法单独验证 | 按五层拆 |
| 渲染函数里顺手改状态 | 渲染无法单独验证 | 渲染只返回字符串/对象 |
| 多处各自解析同一存储键 | 「数据未接通」 | 唯一事实源 + 变更广播 |
| 动态 HTML 拼 `onclick` | 名字含引号炸页面 | `data-*` + 事件委托 |
| 入口文件统一注册所有页面钩子 | 静默吞钩子 | 谁拥有页面谁注册 |

### 验证方式（拆完必须能证明）

- 渲染层纯度：断言源码**不含 `document.`**
- 数据层唯一性：断言该存储键的写操作**只出现在事实源模块**
- 控制器连通性：桩里 `navigate('vX')` 后断言关键控件**非空**

### 3.7 GitHub Actions 无头浏览器验收

这是云端自动验收，不是手机浏览器预览，也不是 APK 安装测试。

有 Web 前端的 App，在构建 APK 前必须跑 `.github/workflows/browser-acceptance.yml`。它在 GitHub Actions 的 Ubuntu 虚拟机里启动无头 Chromium，打开本地页面，自动执行点击、输入、切换和刷新。手机里的 ProotLinux 不安装浏览器，本地服务能打开不算这项验收通过。

工作流顺序：

1. 检出当前提交。
2. 安装 Node.js、Playwright 和 Chromium。
3. 启动本地 HTTP 服务。
4. 无头浏览器走完 App 的真实主流程。
5. 断言关键结果可见，并检查页面没有未处理错误。
6. 失败时上传截图、控制台日志和测试报告。

最低要求：

- 页面打开后关键按钮可以点击。
- 输入框可以填写，结果会显示在页面上。
- 刷新后本地保存的数据还在。
- 页面错误和异步错误都能被测试发现。
- 失败必须保留证据，不能只看退出码。

无头浏览器验收通过，只说明 Web 主流程通过。它不代替主人的手机视觉确认，也不证明 APK 已安装可用。

### 3.8 报错助手（所有 App 必加）

每个 App 都必须有可见的报错助手，用来把隐藏错误直接显示在页面上。只写 `console.error`、只弹短提示或静默失败，都不算完成。

报错助手至少覆盖：

- 按钮操作中的同步异常。
- 接口请求失败、超时、返回空内容和字段缺失。
- 未处理的异步错误。
- 输入不完整、格式错误和越界数据。

显示规则：

- 错误出现在页面顶部或固定错误区，不能被正常提示盖住。
- 显示完整错误原因；有文件名和行号时一并显示。
- 用户点击错误区后可以关闭。
- 无头浏览器测试必须断言人为制造的错误能够显示。

### 3.9 环境契约声明（防止本地变砖）

- AI 只负责编辑、测试和触发 CI，绝对禁止在手机 ProotLinux 内部安装 Android SDK/NDK 或尝试本地编译。
- APK 构建必须优先走云端 CI，保护手机存储和运行环境。
- 本地的所有路径访问，统一使用当前共享目录的相对路径。

### 3.10 安全红线与失职台账

- 绝对禁止将任何 Token、密钥写入命令、日志或提交到仓库。
- 所有认证必须通过环境变量或 gh auth 完成，认证失效时必须重新验证，不得硬编码。
- 如果发生 Token 泄露尝试，直接记入 docs/REVIEW-LOG.md（安全与流程失职台账），视为严重违规。

### 3.11 CI 失败诊断规范（禁止盲目重试）

- 云端 CI 失败时，第一步必须是拉取失败步骤的日志（GitHub 用 gh run view --log-failed），禁止直接“重新运行”。
- 必须根据日志区分错误类型：依赖错误、架构错误、签名错误、缓存错误、源码错误。
- 修复后，再重新提交触发工作流，并在回复中附上“失败原因 + 修复动作”的证据。

### 3.12 本地构建降级策略（设置止损线）

- 如果用户明确要求手机本地构建，允许进入本地构建模式。
- 本地构建必须依次执行：doctor -> Android APK 冒烟测试 -> Rust/NDK 冒烟测试 -> 完整构建。
- 如果真实 ARM64 工具链无法验证，立即停止本地构建，回退到云端 CI，绝对不许绕过检查。

## 6. 硬规矩
